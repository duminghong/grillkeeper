# 需求打磨访谈协议（Grill Protocol）

> **本文档是融合层。** 访谈机制（设计树 / frontier / 问题格式 / 收束条件）的权威源是
> `vendor/grilling/SKILL.disabled.md`；术语表与 ADR 的格式权威源是 `vendor/domain-modeling/`。
> 本文件只做一件事：**在权威机制上叠加"即时审查内循环"**。冲突时以上游为准。

## 入口与机制来源

| 变体 | 权威源 | 行为 |
|---|---|---|
| `grilling` | `vendor/grilling/SKILL.disabled.md` | 基础访谈：设计树 + frontier |

> **隔离规则**：vendor 文本中出现的 `/grilling`、`/domain-modeling` 等 slash 引用，一律解析为本仓库 `vendor/` 下的对应文件，**禁止解析为外部 skill 调用**——即使运行环境恰好安装了同名 skill。

Grillkeeper 阶段一 = `grilling` 访谈 + `domain-modeling` 落文档的组合口径（默认边聊边落文档），审查内循环是本 skill 的增强。

---

## 一、机制骨架（上游权威，必须遵守）

### 设计树（design tree）

把需求/设计映射成一棵**设计树**：每个决策分叉出挂在它下面的子决策。

### frontier（前沿）

> **frontier 是"前置条件已全部落定"的那些决策** —— 即你现在**不用猜尚未听到的答案**就能问出的问题。

- **一轮问完整个 frontier**：给每个问题编号，并**给出你的推荐答案**
- 问完**停下来等用户回答**，再进入下一轮
- 用户回答重塑树 → 已落定的决策把 frontier 向外推 → **重算 frontier** → 问下一轮
- **依赖本轮尚未落定问题的问题，属于后续轮次，不属于本轮**

### 问题格式

```
❓ **Q1** - **<问题标题>**: <问题正文，可多段，可含多个选项>

➡️ <你的推荐答案>
```

推荐答案是**必填**——它把"开放式拷问"变成"可反驳的判断"，用户即使同意也必须显式确认。

### 找事实是你的职责，不是用户的

frontier 问题需要环境事实时（文件系统、工具、仓库状态），**派 sub-agent 去查，不要问用户**。

**不要阻塞**：一个正在跑的探查 = 一个未落定的前置条件，所以**只有它的下游问题需要等**；frontier 里其余问题现在照问。

**决策是用户的** —— 逐个交给用户，然后等。

### 收束

> **frontier 为空时结束**：设计树每个分支都走过，**没有任何东西被默默假设**。

**在用户确认达成共识之前，不要动手实施。**

## 二、Grillkeeper 叠加层（本 skill 的增强）

### 叠加 1：定基调 = 设计树的根节点

上游的 frontier 是"前置已落定的决策"。基调控的是**整棵树的口径**，是天然的根节点，必须在第一轮 frontier 里、且排在最前。

**访谈开始前必问（两问）**：

1. **是否需要向后兼容？**（老数据/老接口/老客户端还能不能用？还是允许 breaking change 一步到位？）
2. **按最彻底的来，还是按最小改动来？**（激进一次到位 vs 保守逐步演进）

**用户给模糊回答（"都行"、"你看着办"）时必须逼二选一** —— 这两个答案会让打磨出的需求和用户预期南辕北辙，带着模糊基调进入后续轮次是最贵的错误。

这两个答案改变后续**所有**节点的口径：

| 基调 | 后续每个节点附加的审查问题 |
|---|---|
| 向后兼容 = 否 + 最彻底 | 可以拷问"直接改 schema / 翻新表结构 / 砍掉旧路径"，不问迁移过渡 |
| 向后兼容 = 是 | 新旧并存期的双写、灰度、回滚路径是否闭环？ |
| 最小改动 | 是否绕开了能复用的现有代码？是否为"彻底"重写了本可保留的部分？ |

### 叠加 2：即时审查 = 树长新分支

上游只有"问答推进"，**没有审查**。Grillkeeper 在两者之间插入一道扫描：

```
本轮问题（整个 frontier，含推荐答案）
   ↓
用户回答
   ↓
【叠加】对每个回答做即时审查扫描
   ↓
审查发现的问题 → 变成新的树节点（以该决策为前置）→ 进入 frontier
   ↓
已确认决策 → 增量落文档（CONTEXT.md / ADR / 打磨记录）
   ↓
frontier 快照 / 未落定节点 / 破防清单 → 追加到 .grillkeeper/session.md（见叠加 7）
   ↓
重算 frontier（= 上游原步骤）
   ↓
frontier 为空？—— 否 → 下一轮 ／ 是 → 收束
```

**关键**：审查发现不是"临时追问"，而是**正式挂进设计树的新节点**。这样它不可能被漏掉——只要还有未落定的 🔴/🟡 审查发现，frontier 就非空，访谈就不会结束（🟢 级不挂节点，门槛见叠加 3）。

### 叠加 3：每轮扫描的分级（A 组必跑 / B 组信号触发）

内循环扫描共 14 项，分两组。**A 组每轮必跑**，一句话级别；**B 组命中信号才跑**，命中时同样一句话带过，不展开。

**A 组 — 每轮必跑（3 项）**：

| 检查项 | 审查问题 |
|--------|---------|
| 断头路 | 这个方案有没有只考虑了成功路径？失败了怎么办？ |
| 自相矛盾 | 与之前已落定的其他决策是否矛盾？ |
| 越权依赖 | 是否暗示了不应存在的模块调用关系？ |

**B 组 — 命中信号才跑（11 项）**：

| 检查项 | 触发信号 | 审查问题 |
|--------|---------|---------|
| 过度设计 | 出现新抽象层/新组件 | 是否为了正确性把强一致做到了不必要的地方？ |
| 设计不足 | 出现新开关/新接口 | 是否有"只有开关没有实体/状态机/补偿"的半成品？ |
| CAP/BASE 矛盾 | "强一致/实时"诉求撞上异步方案 | 业务要求强一致但方案用了异步/最终一致？ |
| 可复现风险 | 任何 🟡 以上发现落笔时 | 能否给出触发条件 + 级联路径 + 全崩结果？ |
| 专家推荐 | 决策命中 routing-matrix 信号 | 对照内置工程清单，最佳实践是什么？当前方案是否最优？ |
| 风险标注 | 任何审查发现落笔时 | 如果这个决策实现后有缺陷，影响面有多大？（Iron Law 四段式） |
| 破防场景回归 | 破防场景清单非空 | 把清单回放给新方案，确认没被新决策重新引入（防"修了 A 引入 B"） |
| 术语钉住 | 出现新概念/新名词 | 是否与已有术语同名异义/同义异名？抓到即刻写入 `CONTEXT.md` |
| 可测性追问 | 决策即将落定 | 这个决策怎么测、怎么验证它在线上是对的？（设计阶段补最便宜） |
| 复用/YAGNI | 提出新依赖/新模块/重写 | 现有依赖/平台特性是否已经覆盖？防访谈越聊越复杂 |
| ADR 判定 | 决策落定时 | 是否满足"难逆转 + 无上下文则困惑 + 真实权衡"三条？不满足就不写 ADR |

**节点挂载门槛**：仅 🔴 Critical / 🟡 Warning 级发现挂为 frontier 新节点；🟢 级直接记入打磨记录"残余观察"，不挂节点、不阻塞收束。

**轮次预算**：超过 **15 轮** frontier 仍非空 → 暂停提问，列出全部残余节点请用户裁决（接受为残余风险 / 继续拷问 / 叫停），不允许无界循环。

### 叠加 4：条件触发（只在命中信号时跑）

| 能力 | 触发信号 | 动作 |
|------|---------|------|
| 容量/成本粗算 | 涉及并发数、数据量、DB 往返 | 当场算量级：链路 DB 往返数 × 单次延迟；重试期望 = 1/(1-冲突率)；对照 `engineering-checklists.md` § performance-and-capacity |
| 威胁建模 | 出现新信任边界（外部回调、用户输入、跨租户） | 过一遍输入校验/注入面/越权/凭据，对照 § secure-sdlc-and-threat-modeling |
| 数据契约检查 | 涉及跨服务 payload / schema 演化 | 加字段 OK、改字段名禁止、版本策略；对照 § event-workflows |
| 原型验证 | 状态机/复杂分支拿不准 | 中断访谈，生成一次性 HTML 原型（单文件、无依赖）验证分支，验证完继续 |
| 历史记忆回查 | 话题命中本仓库既往决策 | 查 `CONTEXT.md` / `docs/adr/` / `.brooks-lint-history.json`，避免重复踩坑 |

### 叠加 5：禁止项（防止拖死节奏）

- ❌ **完整 Mermaid 依赖图重绘** —— 收敛后画一次就够
- ❌ **Health Score 每轮重算** —— 方案没定稿前分数无意义
- ❌ **全量十二书风险扫描** —— 内循环只跑叠加 3 的 A 组三项 + 命中信号的 B 组，全量扫描留给阶段二完整审查
- ❌ **每轮重读 vendor 原文** —— 内循环只对照本文件清单扫描；vendor 全文仅在首次进入阶段或命中具体条目时读一次

### 叠加 6：文档落盘纪律（遵循上游 `domain-modeling`）

**术语** → 解析出的那一刻**立即**写入 `CONTEXT.md`，不要批量攒着。格式见 `vendor/domain-modeling/CONTEXT-FORMAT.md`（每条 1–2 句，列出 `_Avoid_` 同义词；只收本上下文特有概念，通用编程概念不收）。

**ADR** → **克制**，只在三条**全部**为真时才写：

1. **难逆转** —— 日后改主意的代价是真实的
2. **无上下文则困惑** —— 未来读者会问"为什么他们要这样做"
3. **真实权衡的结果** —— 存在真正的备选，且是因特定理由选中的

任一不满足就跳过。格式见 `vendor/domain-modeling/ADR-FORMAT.md`（存放 `docs/adr/`，顺序编号，可以只有一段话）。

> 对比：本协议旧版本要求"每个 ✅ 决策都写一行 ADR"，这与上游"ADR 要克制"直接冲突，已废弃。多数决策留在打磨记录里即可。

### 叠加 7：会话状态落盘（`.grillkeeper/session.md`）

设计树结构、frontier 状态、未落定问题、破防场景清单默认只存在于对话上下文——长访谈遇会话中断/上下文压缩即丢失，且**静默丢失**（没人知道丢了什么）。补一条工作文件纪律：

- **创建**：第一轮定基调两问落定后，在用户工作区根目录创建 `.grillkeeper/session.md`
- **每轮追加**：frontier 快照（未落定节点编号 + 标题）、本轮新挂的 🔴/🟡 审查发现、破防场景清单当前状态
- **恢复**：访谈中断后重启，第一个动作 = 读 `session.md` 重建设计树与 frontier，向用户口头确认后继续；**禁止凭记忆续跑**
- **收束**：用户确认收束、打磨记录（§四）产出后，`session.md` 使命完成，可删除或归档

## 三、设计树的种子分支

树的形状由回答决定，不预设轮次。以下是**初始化 frontier 时的典型分支**，按依赖顺序自然展开——不是固定问卷，命中即用：

| 分支 | 典型问题 |
|------|---------|
| 边界 | 解决什么问题？不做什么？成功标准是什么？ |
| 场景 | 核心路径？异常路径？边界条件（并发数/数据量/超时量级）？ |
| 方案 | 有哪些可选方案（含"不做"）？各自代价（开发/运维/认知/迁移）？推荐哪个？ |
| 风险 | 最可能在哪爆？爆了怎么发现？爆了怎么兜底？ |
| 文档 | 结论写到哪里？谁需要知道？什么时候重新评估？ |

**节点的"落定"判定**（即什么算 settled，可以移出 frontier）：

1. 异常路径都有处理方案（不能只有"返回错误"）
2. 关键决策通过了即时审查（无未解决的 🔴 Critical 子节点）
3. 风险都有可观测监控 + 可执行兜底（不能只有"人工介入"）
4. 涉及多模块的决策都有明确的利益相关方确认
5. 决策都有可测性答案
6. 破防场景清单经回归确认，无被新决策重新引入的场景

## 四、输出格式

### 每轮附加的审查结论

```markdown
**即时审查**: 第 N 轮 — <审查结论>
- ✅ 已落定: <决策> — 审查通过
- 🟡 <问题> — 已挂为树节点 Q<x>
- 🔴 <问题> — 已挂为树节点 Q<x>，阻塞其下游
```

### 收束时的打磨记录

```markdown
## 需求打磨记录（含即时审查）— <需求名称>

**原始需求**: <一句话描述>

**访谈基调**: 向后兼容 = <是/否> | 彻底程度 = <最彻底/最小改动>

**设计树**:
- Q1 <根节点> → 已落定
  - Q2 <子决策> → 已落定
  - Q3 <审查发现衍生的子决策> → 已落定

**已落定决策**:
1. <决策1> ✅ — 可测性：<验证方式>
2. <决策2> ✅ — 可测性：<验证方式>

**审查发现（已处理）**:
- <发现1> 🟡 — 转为 Q<x> → <用户回答> → 已落定
- <发现2> 🔴 — 转为 Q<x> → <用户回答> → 已落定

**破防场景回归**: 最后一轮已回放 N 个场景，全部未被重新引入 ✅

**术语表**: 已写入 `CONTEXT.md` 的术语 <列表>

**ADR**: <已创建的 ADR 路径；若无，说明为何三条件未全满足>

**残余风险**:
- <风险> — 已接受，触发条件：<...>，兜底：<...>

**建议文档**: <应写入的文档路径>
```
