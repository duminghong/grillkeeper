# 文档写作风格规范

> Grillkeeper 内置文档产出规范：覆盖意图识别、体裁选择、写作纪律与内置模板

## 核心原则

1. **实质重于形式**：结构服务内容，而非约束内容
2. **自然表达**：避免翻译腔、企业黑话、工作狂语言
3. **证据支撑**：所有论断必须有证据，无量化不修饰
4. **一次说透**：结论只在一个权威位置完整表述，其它部分引用时必须提供新证据或新角度

## 禁用清单

### 任务描述禁用
- "可操作"、"可执行"、"检查清单"、"可参考"、"定期复盘"、"x 天行动计划"
- "actionable checklist"、"30-day action plan"、"weekly review cadence"
- 把人类经验框架化为可优化工作流

### 内容正文禁用
- 虚动词结构："进行/开展/实施" + 名词 → 直接用动词
- 无证据修饰："确保/非常/极其/highly/extremely/significantly" + 无量化证据
- 空泛最高级："world-class"、"cutting-edge"
- 自创抽象名词堆砌：每段最多 1 个自创概念，其余用具体描述替代
- 对比修辞："不是…而是…"、"真正的问题不是…而是…"、"本文试图…"
- 元叙述："下面我们来看…"、"接下来将详细分析…"
- 标题复述：章节首句不得重复标题已说的内容

### 格式纪律
- 标题不带标点（句号、冒号、问号）
- 每段 3-8 句，重点段落更短
- 加粗仅限：专有名词、工具/命令名、关键警告
- 禁止加粗+斜体叠加（***text***）
- 无 emoji，除非用户明确要求

## 结构选择

| 类型 | 适用场景 | 特点 |
|------|---------|------|
| Structured | 技术文档、报告、教程、PRD | 清晰章节、编号步骤、组织框架 |
| Narrative | 产品发布故事、营销文案、品牌叙事 | 讲故事流程、场景设置、示例驱动 |
| Free-form | 探索性分析、早期发现笔记 | 有机想法发展、灵活组织 |
| Hybrid | 复杂交付物、长篇分析 | 叙事引入 → 结构化主体 → 反思结论 |

## 视觉元素

- ≥3 个可比数据点 → 必须配图
- 趋势/排名/占比 → 优先图表而非文字
- 流程/架构/关系 → 优先图表而非文字
- 图表必须有标题和 alt-text
- 图表紧跟相关分析段落，不堆在附录

## 模板骨架摘要

### PRD

必备段落：背景与目标（量化成功标准）→ 用户场景（核心路径 + 异常路径）→ 功能需求（逐条带验收标准）→ 非功能需求（性能/安全/兼容指标）→ 范围外（明确不做什么）→ 依赖与风险。
质量红线：每条需求可测试；每个指标有数字；异常路径不得只写"提示错误"。

### 竞品分析

必备段落：分析目标 → 玩家清单（分层：直接/间接/潜在）→ 逐玩家档案（定位/核心能力/价格/优劣）→ 维度对比表 → 差距与机会。
质量红线：对比维度 ≤7 个；每个论断有证据来源；不写"各有千秋"式废话结论。

### 架构设计文档（HLD/LLD）

必备段落：上下文与约束 → 候选方案（≥2 个，含代价对比）→ 选定方案与理由 → 模块划分与依赖方向 → 关键链路时序 → 数据模型 → 失败与补偿路径 → 容量估算。
质量红线：只有成功路径的设计文档直接打回；依赖图必须画出；取舍必须写明放弃了什么。

### 技术文档

必备段落：这文档给谁看 → 前置条件 → 任务式步骤（每步可验证）→ 故障排查表（症状→原因→处置）→ 边界与限制。
质量红线：步骤必须可照做复现；禁止"详见某文档"式悬空指针；命令必须含预期输出。

### 营销文案

必备结构：一个具体用户场景开场 → 痛点 → 产品如何消除痛点（功能→收益，不是功能罗列）→ 证据（数据/案例）→ 行动号召。
质量红线：禁止空洞最高级（"领先""一流"）；每个收益点必须能回答"所以呢"到用户获益为止。

### 白皮书

必备段落：问题定义（行业级）→ 现状与缺口（数据支撑）→ 方法/框架 → 案例验证 → 趋势判断。
质量红线：所有数据有来源；趋势判断标注置信度；不把营销文案包装成白皮书。

### 内部备忘

必备结构：结论先行（第一句说清要什么）→ 背景（≤3 句）→ 依据 → 需要读者的动作与截止时间。
质量红线：超过一屏的备忘拆成多篇；禁止"请知悉"式无动作结尾。
