# 架构破坏专家检查清单

> **权威源：`vendor/architecture-breaker-review/SKILL.disabled.md`**，本文件为其清单摘录 + 速查。冲突以 vendor 为准。
> 五维度扫描，每个发现必须带可复现的破防场景；发现按 **F1..Fn 编号**。
>
> 上游两条硬性原则：
> - **Iron Law**：每个发现 `Symptom → Source → Consequence → Remedy` 四段式，缺一不算发现，只是噪声
> - **破防场景必须给到"可复现条件"**：不是"系统会崩"，而是"当 XX 条件发生时，系统会彻底崩溃，触发路径是……"
>
> 上游明纪律（本清单不重复细节）：
> - **只读审查**：不写代码、不改文件；用户要求落地再执行
> - **好的基建显式 credit**（outbox/多实例隔离/补偿矩阵），但同类问题别重复挑刺
> - 整改建议要能**直接落回文档/代码路径**（给出目标文件/服务名）
> - 可选 Health 重算：整改被采纳时，说明剔除哪几条 Critical 后分数变化

## 0. 范围与证据（先确立，再挑刺）

1. 明确审查对象：模块 / 切片（如支付/下单）/ 整套架构；**没给就用仓库 + planning 自动定范围**（模块速查表、依赖图、结算/补偿矩阵所在文档）
2. 逐条核验：任何关键论断必须对照实文/实码确认，标注"已核验 ✅ / 实文不符 ❌"——宁可多读几页文档，不许凭印象下结论
3. 输出 Mermaid 依赖图（nodes=模块/服务，dashed 标越权边/circular），扫完再上色 red/yellow/green

## 1. 战略合理性审查

- [ ] 判断"过度设计" vs "设计不足"
  - 过度设计：为正确性把强一致做到没必要处
  - 设计不足：只有成功路径、无失败/补偿路径，或"只有开关没有实体/状态机"
- [ ] 至少给出 2 个能让项目夭折的技战术误判
  - 单点被放大成"全场冻结"
  - 半成品开关/接口（有开关无实体/状态机/退款/库存协调）
  - 为扩展性引入的抽象/多层转换，成本没量化

## 2. 逻辑闭环与矛盾点挖掘（重点）

- [ ] 断头路：核心链路里找"只有成功路径"
  - 失败了怎么办？超时会怎样？回调丢了谁兜底？
- [ ] CAP/BASE 取舍点：业务要强一致，技术用了异步 MQ/动态档位
  - 每个取舍点必须给出具体脏数据场景
- [ ] 一致性窗口量化：异步路径兜底 Job 的延迟/周期
  - 算出"最长不一致窗口"，说明窗口内对其它判定的影响

## 3. 模块分布与边界清晰度

- [ ] 循环依赖 / 跨层直调
  - 对照依赖红线，找出"本不该反向调用的模块 A 直调了模块 B"
  - Web 层调 DAO、业务域调房态/订单状态机都算
- [ ] 单一职责：哪个模块承担了"不该它管的杂事"
  - 给出拆分建议（命名到服务粒度）
- [ ] 同名异义：两个语义不同的概念同名
  - 点名并建议显式区分

## 4. 生产环境生存能力

- [ ] 超时/重试/幂等/熔断/降级矩阵是否完整
  - 外向超时值、重试策略（次数+退避+死信）、幂等键（唯一索引）、熔断半开、舱壁隔离、降级预案
- [ ] TraceId 透传 + 黄金指标
  - 跨异步通道（回调→outbox→MQ→WS/短信）是否一个 TraceId 串到底
  - 核心链路有没有"成功率/时长/P99"命中类指标
- [ ] 资源预估偏差
  - DB 连接池/内存/single-node 预算是否已无余量
  - 超 90% 就必须提示扩容阈值

## 5. 三类专项矛盾

### ① 数据一致性矛盾
- [ ] 并发覆盖风险（同一行/键被两个异步写入）
- [ ] 极端情况下的不一致时间窗口（用兜底 Job 延迟、轮询周期、消息延迟给出量级）
- [ ] 每个幂等键是否真的唯一

### ② 抽象与性能矛盾
- [ ] 量化 RT 代价：链路 DB 往返数
- [ ] 重试期望 = 1/(1-冲突率)
- [ ] 给出"值不值"的一句话结论 + 最划算的优化

### ③ 资源隔离矛盾
- [ ] 核心业务 vs 非核心业务是否共用线程池/连接池/进程/存储
- [ ] 模拟一条 Full GC/长查询如何拖垮核心的小路
  - 大导出压满共享 PG IO → 核心轮询超窗口 → 被关单 → 触发自动退款风暴

## 破防场景（可复现）

每个 Critical 发现必须给出：
- **触发条件**：什么条件下发生
- **级联路径**：从触发到崩溃的完整链路
- **全崩结果**：系统彻底崩溃的表现

## 严重度分级

| 严重度 | 判定标准 |
|--------|---------|
| 🔴 Critical | 断头路、单点放大、越权环、半成品 |
| 🟡 Warning | 资源/可观测/窗口未量化 |
| 🟢 Suggestion | 文档措辞/命名/映射 |

## Health Score（本模式专用）

权重见权威源 `vendor/architecture-breaker-review/SKILL.disabled.md` § 输出模板，此处不抄数字防摘录漂移。
**纪律**：本模式权重与 brooks-lint 不同——按模式各从其源，报告中必须明确列出实际所用权重，禁止混用。

## 常见破防模式索引（记忆用，非模板）

- 越权环：新模块直调房态/订单状态机建房建单 → 翻转为事件订阅
- 多重取价：快照价 + 动态档位 + 覆盖字段三源并存 → 锁死单一路径
- noeviction 单点冻结：为防静默丢 key 用了不允许淘汰 → 写满全店停摆
- 半成品预购：有开关无实体/状态机/退款/库存协调 → 砍掉或补状态机
- 宽事务自激振荡：N×SKU 一次原子预占撞乐观锁 → RT 放大 + 店员重复开台
- 共存储 Full GC：worker 进程隔离了但同一 PG 存储没隔离 → 加 IO 水位闸门
